### Configuration Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `experiment_id` | string | Unique identifier for the workflow run |
| `suffix_time` | boolean | Auto-append timestamp to experiment_id |
| `parca_options.cpus` | integer | CPU cores for parameter calculator |
| `generations` | integer | Number of cell division generations |
| `n_init_sims` | integer | Number of initial simulations per variant |
| `single_daughters` | boolean | Simulate only one daughter per division |
| `emitter` | string | Output format: "parquet", "timeseries", "database" |
| `emitter_arg.out_dir` | string | Absolute path for output directory |
| `aws_cdk.container_image` | string | Path to Singularity .sif image |
| `aws_cdk.build_image` | boolean | Whether to build image (false = use existing) |
| `aws_cdk.wait` | boolean | Block until workflow completes |

## Generated SLURM Submission Scripts

### Main Nextflow Orchestration Job

This script is generated by `workflow.py` and submitted via `sbatch`:

```bash
#!/bin/bash
#SBATCH --job-name=nf-{experiment_id}
#SBATCH --time=7-00:00:00
#SBATCH --cpus-per-task 1
#SBATCH --mem=4GB
#SBATCH --partition=jobs-queue
#SBATCH -o /mnt/fsx/home/svc_vivarium/sms_api/prod/repos/1c2d69f/vEcoli/slurm_logs/nf-{experiment_id}.out
#SBATCH -e /mnt/fsx/home/svc_vivarium/sms_api/prod/repos/1c2d69f/vEcoli/slurm_logs/nf-{experiment_id}.err

set -e
export JAVA_HOME=$HOME/.local/bin/java-22
export PATH=$JAVA_HOME/bin:$HOME/.local/bin:$PATH
nextflow -C {config_path} run {workflow_path} -profile aws_cdk \
    -with-report {report_path} -work-dir {workdir}
```

**Template Variables:**
- `{experiment_id}` - From config JSON
- `{config_path}` - Path to generated `nextflow.config`
- `{workflow_path}` - Path to generated `main.nf`
- `{report_path}` - Path for Nextflow HTML report
- `{workdir}` - Nextflow working directory

### Individual Task Jobs (Nextflow-generated)

Nextflow submits individual SLURM jobs for each task. Resource allocation per profile settings:

**ParCa Job:**
- CPUs: `parca_options.cpus` (from config)
- Memory: `cpus * 2GB`
- Time: 1 hour (scales on timeout)

**Simulation/Analysis Jobs:**
- CPUs: 1
- Memory: 4GB (scales to 8GB, 12GB on OOM retry)
- Time: 4 hours (scales on timeout retry)
- Max retries: 3

## Nextflow Profile Configuration

The `aws_cdk` profile in `runscripts/nextflow/config.template`:

```groovy
aws_cdk {
    process {
        withLabel: parca {
            cpus = params.parca_cpus
            memory = params.parca_cpus * 2.GB
            time = {
                if ( task.exitStatus == 140 ) {
                    1.h * task.attempt
                } else {
                    1.h
                }
            }
        }
        executor = 'slurm'
        queue = 'jobs-queue'
        clusterOptions = ''
        cpus = 1
        memory = {
            if ( task.exitStatus in [137, 140] ) {
                4.GB * task.attempt
            } else {
                4.GB
            }
        }
        time = {
            if ( task.exitStatus == 140 ) {
                4.h * task.attempt
            } else {
                4.h
            }
        }
        errorStrategy = {
            ((task.exitStatus in [137, 140, 143, Integer.MAX_VALUE])
            && (task.attempt <= process.maxRetries)) ? 'retry' : 'ignore'
        }
        maxRetries = 3
        container = params.container_image
        containerOptions = "-B ${params.publishDir}:${params.publishDir} -B ${launchDir}:${launchDir}"
    }
    singularity.enabled = true
    params.projectRoot = '/vEcoli'
    executor.queueStatInterval = '2 min'
    executor.pollInterval = '30 sec'
    executor.exitReadTimeout = '10 min'
    workflow.failOnIgnore = true
}
```

### Manual Execution

```bash

```

### Programmatic Execution (for automation)

The workflow can be triggered programmatically by:

1. **Generate config JSON** with required parameters
2. **Set environment variables**: `SLURM_PARTITION`, `SLURM_LOG_BASE_PATH`
3. **Execute workflow.py** with the config path

```python
import subprocess
import os
import json

# Set environment
os.environ['SLURM_PARTITION'] = 'jobs-queue'
os.environ['SLURM_LOG_BASE_PATH'] = '/mnt/fsx/.../slurm_logs'

# Create config
config = {
    "experiment_id": "automated-run-001",
    "suffix_time": False,
    "parca_options": {"cpus": 2},
    "generations": 1,
    "n_init_sims": 1,
    "emitter": "parquet",
    "emitter_arg": {"out_dir": "/mnt/fsx/.../out"},
    "aws_cdk": {
        "container_image": "/mnt/fsx/.../vecoli.sif",
        "build_image": False
    }
}

# Write config
config_path = "/tmp/workflow_config.json"
with open(config_path, 'w') as f:
    json.dump(config, f)

# Execute (from venv)
result = subprocess.run(
    ["python", "runscripts/workflow.py", "--config", config_path],
    cwd="/mnt/fsx/.../vEcoli",
    capture_output=True,
    text=True
)

# Returns SLURM job ID in stdout: "Submitted batch job 123"
job_id = result.stdout.strip().split()[-1]
```

## Monitoring and Troubleshooting

### Check SLURM Queue

```bash
squeue                          # All jobs
squeue -u $USER                 # Your jobs
squeue -j <job_id>              # Specific job
```

### Check Job Status

```bash
scontrol show job <job_id>
```

### View Logs

```bash
# Main workflow log
tail -f slurm_logs/nf-{experiment_id}.out

# Nextflow detailed log
tail -f out/{experiment_id}/nextflow/.nextflow.log
```

### Common Exit Codes

| Code | Meaning | Action |
|------|---------|--------|
| 137 | OOM Killed | Memory scaled up on retry |
| 140 | Time Limit | Time scaled up on retry |
| 143 | Preemption | Automatic retry |

### Resume Failed Workflow

```bash
python runscripts/workflow.py --config configs/my_config.json --resume {experiment_id}
```

- Singularity/Apptainer runtime

- Python 3.12 with all vEcoli dependencies

## Integration Notes

For service integration, the key touchpoints are:

1. **Config Generation**: Create JSON config with experiment parameters
2. **Environment Setup**: Set `SLURM_PARTITION` and `SLURM_LOG_BASE_PATH`
3. **Workflow Trigger**: Execute `python runscripts/workflow.py --config <path>`
4. **Job Tracking**: Parse "Submitted batch job {id}" from stdout
5. **Status Monitoring**: Use `squeue`/`scontrol` or check SLURM logs
6. **Output Retrieval**: Read from `out/{experiment_id}/` after completion
