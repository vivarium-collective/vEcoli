### Configuration Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `experiment_id` | string | Unique identifier for the workflow run |
| `suffix_time` | boolean | Auto-append timestamp to experiment_id |
| `parca_options.cpus` | integer | CPU cores for parameter calculator |
| `generations` | integer | Number of cell division generations |
| `n_init_sims` | integer | Number of initial simulations per variant |
| `single_daughters` | boolean | Simulate only one daughter per division |
| `emitter` | string | Output format: "parquet", "timeseries", "database" |
| `emitter_arg.out_dir` | string | Absolute path for output directory |
| `aws_cdk.container_image` | string | Path to Singularity .sif image |
| `aws_cdk.build_image` | boolean | Whether to build image (false = use existing) |
| `aws_cdk.wait` | boolean | Block until workflow completes |

## Generated SLURM Submission Scripts

### Main Nextflow Orchestration Job

This script is generated by `workflow.py` and submitted via `sbatch`:

```bash
#!/bin/bash
#SBATCH --job-name=nf-{experiment_id}
#SBATCH --time=7-00:00:00
#SBATCH --cpus-per-task 1
#SBATCH --mem=4GB
#SBATCH --partition=jobs-queue
#SBATCH -o /mnt/fsx/home/svc_vivarium/sms_api/prod/repos/1c2d69f/vEcoli/slurm_logs/nf-{experiment_id}.out
#SBATCH -e /mnt/fsx/home/svc_vivarium/sms_api/prod/repos/1c2d69f/vEcoli/slurm_logs/nf-{experiment_id}.err

set -e
export JAVA_HOME=$HOME/.local/bin/java-22
export PATH=$JAVA_HOME/bin:$HOME/.local/bin:$PATH
nextflow -C {config_path} run {workflow_path} -profile aws_cdk \
    -with-report {report_path} -work-dir {workdir}
```

**Template Variables:**
- `{experiment_id}` - From config JSON
- `{config_path}` - Path to generated `nextflow.config`
- `{workflow_path}` - Path to generated `main.nf`
- `{report_path}` - Path for Nextflow HTML report
- `{workdir}` - Nextflow working directory

### Individual Task Jobs (Nextflow-generated)

Nextflow submits individual SLURM jobs for each task. Resource allocation per profile settings:

**ParCa Job:**
- CPUs: `parca_options.cpus` (from config)
- Memory: `cpus * 2GB`
- Time: 1 hour (scales on timeout)

**Simulation/Analysis Jobs:**
- CPUs: 1
- Memory: 4GB (scales to 8GB, 12GB on OOM retry)
- Time: 4 hours (scales on timeout retry)
- Max retries: 3

## Nextflow Profile Configuration

The `aws_cdk` profile in `runscripts/nextflow/config.template`:

```groovy
aws_cdk {
    process {
        withLabel: parca {
            cpus = params.parca_cpus
            memory = params.parca_cpus * 2.GB
            time = {
                if ( task.exitStatus == 140 ) {
                    1.h * task.attempt
                } else {
                    1.h
                }
            }
        }
        executor = 'slurm'
        queue = 'jobs-queue'
        clusterOptions = ''
        cpus = 1
        memory = {
            if ( task.exitStatus in [137, 140] ) {
                4.GB * task.attempt
            } else {
                4.GB
            }
        }
        time = {
            if ( task.exitStatus == 140 ) {
                4.h * task.attempt
            } else {
                4.h
            }
        }
        errorStrategy = {
            ((task.exitStatus in [137, 140, 143, Integer.MAX_VALUE])
            && (task.attempt <= process.maxRetries)) ? 'retry' : 'ignore'
        }
        maxRetries = 3
        container = params.container_image
        containerOptions = "-B ${params.publishDir}:${params.publishDir} -B ${launchDir}:${launchDir}"
    }
    singularity.enabled = true
    params.projectRoot = '/vEcoli'
    executor.queueStatInterval = '2 min'
    executor.pollInterval = '30 sec'
    executor.exitReadTimeout = '10 min'
    workflow.failOnIgnore = true
}
```

### Programmatic Execution (for automation)

The workflow can be triggered programmatically by:

1. **Generate config JSON** with required parameters
2. **Set environment variables**: `SLURM_PARTITION`, `SLURM_LOG_BASE_PATH`
3. **Execute workflow.py** with the config path

```python
import subprocess
import os
import json

# Set environment
os.environ['SLURM_PARTITION'] = 'jobs-queue'
os.environ['SLURM_LOG_BASE_PATH'] = '/mnt/fsx/.../slurm_logs'

# Create config
config = {
    "experiment_id": "automated-run-001",
    "suffix_time": False,
    "parca_options": {"cpus": 2},
    "generations": 1,
    "n_init_sims": 1,
    "emitter": "parquet",
    "emitter_arg": {"out_dir": "/mnt/fsx/.../out"},
    "aws_cdk": {
        "container_image": "/mnt/fsx/.../vecoli.sif",
        "build_image": False
    }
}

# Write config
config_path = "/tmp/workflow_config.json"
with open(config_path, 'w') as f:
    json.dump(config, f)

# Execute (from venv)
result = subprocess.run(
    ["python", "runscripts/workflow.py", "--config", config_path],
    cwd="/mnt/fsx/.../vEcoli",
    capture_output=True,
    text=True
)

# Returns SLURM job ID in stdout: "Submitted batch job 123"
job_id = result.stdout.strip().split()[-1]
```

### Common Exit Codes

| Code | Meaning | Action |
|------|---------|--------|
| 137 | OOM Killed | Memory scaled up on retry |
| 140 | Time Limit | Time scaled up on retry |
| 143 | Preemption | Automatic retry |

```bash

```

## Container-Based Workflow Execution (Recommended)

This approach runs `workflow.py` inside the Singularity container and creates a fully self-contained output directory. This is the recommended method for automated/service integration.

### Why This Approach?

- **No Python dependencies on submit node**: Only Java/Nextflow needed on host
- **Self-contained output**: All Nextflow files copied to output directory
- **No host repo dependency**: Uses container's bundled code at runtime
- **Portable**: Output directory can be archived/moved independently

### Overview

The container-based approach involves three steps:
1. Run `workflow.py --build-only` inside the container to generate Nextflow files
2. Copy Nextflow module files from container and update include paths
3. Submit Nextflow job via SLURM

### Configuration Requirements

**Critical**: Set `sim_data_path: null` to force ParCa to run (otherwise workflow.py looks for cached kb files):

```json
{
  "experiment_id": "my-experiment",
  "suffix_time": false,
  "sim_data_path": null,
  "parca_options": {
    "cpus": 2,
    "load_intermediate": null
  },
  "generations": 1,
  "n_init_sims": 1,
  "single_daughters": true,
  "emitter": "parquet",
  "emitter_arg": {
    "out_dir": "/mnt/fsx/home/svc_vivarium/sms_api/prod/my_output"
  },
  "aws_cdk": {
    "container_image": "/mnt/fsx/home/svc_vivarium/sms_api/prod/images/vecoli-{commit}.sif",
    "build_image": false
  },
  "analysis_options": {
    "single": {
      "mass_fraction_summary": {}
    }
  }
}
```

### Step 1: Generate Nextflow Files

Run `workflow.py --build-only` inside the container:

```bash
CONTAINER_IMAGE=/mnt/fsx/home/svc_vivarium/sms_api/prod/images/vecoli-{commit}.sif
CONFIG_PATH=/tmp/workflow_config.json

export SLURM_PARTITION=jobs-queue
export SLURM_LOG_BASE_PATH=/mnt/fsx/home/svc_vivarium/sms_api/prod/my_output/slurm_logs
mkdir -p $SLURM_LOG_BASE_PATH

singularity exec \
    --writable-tmpfs \
    --pwd /vEcoli \
    -B /mnt/fsx:/mnt/fsx \
    ${CONTAINER_IMAGE} \
    python /vEcoli/runscripts/workflow.py \
        --config ${CONFIG_PATH} \
        --build-only
```

**Important flags:**
- `--writable-tmpfs`: Allows writing to container filesystem (for temp files)
- `--pwd /vEcoli`: Sets working directory inside container
- `-B /mnt/fsx:/mnt/fsx`: Bind mounts shared filesystem

This generates files in `{out_dir}/{experiment_id}/nextflow/`:
- `main.nf` - Nextflow workflow
- `nextflow.config` - Nextflow configuration
- `workflow_config.json` - Full merged config

### Step 2: Copy Modules and Fix Include Paths

Copy Nextflow module files from the container to the output directory and update includes to use relative paths:

```bash
NEXTFLOW_DIR=/mnt/fsx/home/svc_vivarium/sms_api/prod/my_output/{experiment_id}/nextflow

# Copy Nextflow module files from container
singularity exec -B /mnt/fsx:/mnt/fsx ${CONTAINER_IMAGE} \
    cp /vEcoli/runscripts/nextflow/sim.nf ${NEXTFLOW_DIR}/
singularity exec -B /mnt/fsx:/mnt/fsx ${CONTAINER_IMAGE} \
    cp /vEcoli/runscripts/nextflow/analysis.nf ${NEXTFLOW_DIR}/

# Update includes to use relative paths (same directory as main.nf)
sed -i "s|from '/vEcoli/runscripts/nextflow/sim'|from './sim'|g" ${NEXTFLOW_DIR}/main.nf
sed -i "s|from '/vEcoli/runscripts/nextflow/analysis'|from './analysis'|g" ${NEXTFLOW_DIR}/main.nf
```

**Note**: The `projectRoot` parameter in `nextflow.config` stays as `/vEcoli` - this is correct because Python scripts run inside the container where `/vEcoli` exists. No additional bind mounts are needed.

### Step 3: Submit Nextflow Job

Create and submit the SLURM batch script:

```bash
#!/bin/bash
#SBATCH --job-name=nf-{experiment_id}
#SBATCH --time=7-00:00:00
#SBATCH --cpus-per-task=1
#SBATCH --mem=4GB
#SBATCH --partition=jobs-queue
#SBATCH -o {slurm_log_path}/nf-{experiment_id}.out
#SBATCH -e {slurm_log_path}/nf-{experiment_id}.err

set -e
export JAVA_HOME=$HOME/.local/bin/java-22
export PATH=$JAVA_HOME/bin:$HOME/.local/bin:$PATH

NEXTFLOW_DIR={output_dir}/{experiment_id}/nextflow

cd ${NEXTFLOW_DIR}
nextflow -C ${NEXTFLOW_DIR}/nextflow.config run ${NEXTFLOW_DIR}/main.nf \
    -profile aws_cdk \
    -with-report ${NEXTFLOW_DIR}/{experiment_id}_report.html \
    -work-dir ${NEXTFLOW_DIR}/nextflow_workdirs
```

### Complete Automation Script

Here's a complete bash script that performs all steps:

    -profile aws_cdk \\

### Known Limitations and Future Improvements

1. **Cached kb detection**: When `sim_data_path` is not explicitly set to `null`, workflow.py may skip ParCa if it finds cached kb files. Always set `sim_data_path: null` for fresh runs.

2. **Submit node requirements**: Still requires Java 22 and Nextflow on the submit node.

3. **Module file copying**: Currently copies `sim.nf` and `analysis.nf` explicitly. If new modules are added, the automation script needs updating.

## Integration Notes

For service integration, the key touchpoints are:

1. **Config Generation**: Create JSON config with experiment parameters (include `sim_data_path: null`)
2. **Environment Setup**: Set `SLURM_PARTITION` and `SLURM_LOG_BASE_PATH`
3. **Container Execution**: Run `workflow.py --build-only` inside Singularity container
4. **Module Copy**: Copy `sim.nf` and `analysis.nf` from container, fix includes to relative paths
5. **Job Submission**: Submit Nextflow via sbatch
6. **Job Tracking**: Parse "Submitted batch job {id}" from stdout
7. **Status Monitoring**: Use `squeue`/`scontrol` or check SLURM logs
8. **Output Retrieval**: Read from `{output_dir}/{experiment_id}/` after completion
